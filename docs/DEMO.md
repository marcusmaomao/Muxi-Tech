# 本地演示指南

这份指南配合电网设备演示数据。数据是本仓库自己编写的，不引用第三方样例库。`MOP_DEMO_SEED=true` 且 `MOP_DEMO_GRID=true` 时，服务启动后会导入本体、样例文档、MySQL 样例表和映射。

## 启动

```bash
cd deploy/compose
cp .env.example .env
docker compose up -d --build
```

浏览器打开 <http://localhost:8899>。

`.env` 里和演示有关的值：

| 变量 | 示例 | 作用 |
|---|---|---|
| `MOP_DEMO_SEED` | `true` | 创建演示租户和管理员 |
| `MOP_DEMO_GRID` | `true` | 导入电网设备演示数据。Compose 默认开启 |
| `MOP_DEMO_ADMIN_USERNAME` | `admin` | 管理员用户名 |
| `MOP_DEMO_ADMIN_PASSWORD` | `demo-admin` | 管理员口令 |
| `MOP_CAPTCHA_EXPOSE` | `true` | 登录接口附带验证码明文，只给本地 |

这是公开的本地口令，不能用于真实环境。

## 演示账号

- 租户：演示租户（`demo`）
- 用户名：`admin`
- 口令：`demo-admin`

## 已经导入的内容

- 项目「电网设备」，命名空间 `https://example.com/ont/grid#`。域名仍是占位。
- 本体：变电站、变压器、线路、巡检记录、设备资产，以及能力问题、术语、两条子类公理和三条关系。
- 样例表：`src_station`、`src_equipment`、`src_line`、`src_inspection`。里面有城东站、一号变压器、城东线和一条巡检记录。
- 数据源「电网样例库」，以及上述四张表的映射。
- 文档「电网设备说明.txt」。

## 演示步骤

1. 登录后打开「项目」，确认有「电网设备」。点「建模」可以看到能力问题、对象和关系。
2. 在建模页点「导出 Turtle」，再点「下载导出文件」。文件里有 `subClassOf`。点「导出 SHACL」得到 `shapes.ttl`。把一份 Turtle 数据贴进校验框，可以看到逐条违规。命名空间仍是占位。
3. 打开「同步」。选择项目「电网设备」、数据源「电网样例库」、对象「变电站」、表 `src_station`。如果这是新环境，映射已经保存过，可以直接预览到「城东站」，然后点「全量同步」。再对变压器、线路、巡检记录各做一次全量同步。
4. 要看增量：对巡检记录做完全量同步后，向 `src_inspection` 插入一行更晚的 `updated_at`，再点「增量同步」。本地也可以用已登录且具备 `runtime:sync` 的令牌调用 `POST /api/v1/demo/grid/inspections`，正文 `{"id":"i2","note":"复检"}`。这个接口只在 `MOP_DEMO_GRID=true` 时存在。
5. 打开「图谱」，类型选「巡检记录」或「变压器」，点「展开邻居」，详情里能看到同步进来的属性。
6. 打开「抽取」。选择项目、文档「电网设备说明.txt」和「模型」页里指向 `http://llm-mock:8080/v1` 的本地模型。抽取结果应带原文「一号变压器安装在城东站」。通过审核后点「发布已通过」，再回到图谱展开邻居。Compose 里的 llm-mock 会按本体清单返回变压器和变电站；类型或属性对不上的结果会进隔离区，不会发布。
7. 打开「系统」里的「日志」，可以用用户名或动作检索登录和操作记录。

## 分支

打开项目里的「画布」可以拖入或点选对象，连父类，自动布局后保存视图。同名继承冲突和导出规则不变。打开左侧「版本」。可以查看提交，从 main 拉出分支，在该分支上建模，再比较两个分支的字段差异。同一字段两边都改过时，在合并请求里选择保留来源或目标，然后合并。表单建模里一个对象可以选多个父类；导出的 Turtle 会为每个父类写 `subClassOf`。两个父类有同名属性时，子类要勾选「重定义继承属性」。演示也可以继续直接改 main。命名空间仍是每个项目自己的占位 URI，没有正式域名，也不部署远程预览。
